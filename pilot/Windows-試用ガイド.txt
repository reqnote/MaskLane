MaskLane  Windows 試用ガイド

■ 試用担当者の準備

Windows x64 の試用端末で、Kiro IDE の標準エージェントを使います。
現在の Kiro のプロキシ設定を控え、対象の通信が通るまで架空データだけを使ってください。

1. ZIP を展開し、試用者と同じ Windows アカウントで MaskLane.exe を起動します。
   ブラウザーに送信状況とマスキングルールの画面が開きます。試用中は起動したウィンドウを開いたままにします。
   ポートを変える場合は MaskLane.exe -proxy-port 18889 のように起動します。

2. 試用担当者が、社内の手順に沿ってこの端末で生成された ca.pem を Kiro から信頼できるように設定します。
   保存先は %LOCALAPPDATA%\MaskingGateway\ca.pem です。
   試用ユーザーの Windows 信頼ストアに登録する場合は、そのユーザーの PowerShell で次を実行します。

   certutil.exe -user -addstore Root "$env:LOCALAPPDATA\MaskingGateway\ca.pem"

   ca-key.pem はこの端末上でゲートウェイが使う秘密鍵です。登録するファイルは ca.pem です。
   試用終了後に取り消せるよう、certutil.exe -dump でこの証明書の拇印を控えます。

3. Kiro の Settings > Proxy で、MaskLane の「Kiro のプロキシ」に表示されたアドレスを設定します。
   既定は http://127.0.0.1:18888 です。設定を保存し、Kiro を再起動します。
   アプリは Kiro の米国東部と欧州のモデル用 HTTPS 接続を検査します。
   Kiro から先に社内の共通プロキシが必須の環境や別リージョンでは、事前に接続経路を確認してください。

■ 利用者が行う操作

1. 「マスキングルール」で「キーワードを追加」を選び、企業名「青葉物流サービス」、
   案件名「星見データ連携案件」、その他「ALPHA-2048」を個別に登録します。
   いずれも試用用の架空データです。「置換後の表記」は空欄のままにし、
   「空欄時の置換例」で種類ごとの表記を確認します。「個人名」と「社外秘」も選べます。

2. Kiro で試用用のフォルダーを開きます。Kiro パネルの Steering から
   ＋ → Workspace を選び、masking.md を作ります。
   保存先は試用フォルダーの .kiro/steering/masking.md です。
   下の区切り線の間を貼り付けて保存してください。

# マスキング済みのキーワードの扱い

`<pl:company:1>`、`<pl:project:1>`、`<pl:person:1>`、`<pl:confidential:1>`、
`<pl:other:1>` は、送信前に置換されたキーワードです。末尾の数字が異なる場合も同様です。
番号は送信ごとに割り振られます。

これらは入力済みのキーワードとして扱い、回答や編集案にも受け取った表記をそのまま使ってください。
元のキーワードの推測や聞き直しは省いてください。
作業に必要なほかの情報が不足している場合は、その項目だけ確認してください。
ここまで

3. チャットに直接入力して試します。

   青葉物流サービスの星見データ連携案件（管理コード ALPHA-2048）について、
   企業名、案件名、管理コードを含めて「日次で受注CSVを取り込む」という
   作業概要を一文にしてください。

   MaskLane に「マスキングして送信しました」と表示され、企業名・案件名・その他が
   それぞれ 1 種類と出ることを確認します。Kiro の回答にも置換後の表記が残ることを確認します。
   一覧の「置換後の表記」で送信時に使われた表記を照合できます。送信が複数ある場合は
   「最近の通信」で時刻を見て、対象の送信を選びます。ルールを変更した後は新しい送信から照合できます。

4. 同梱の kiro-sample.txt を試用フォルダーにコピーします。
   新しいチャットで #file を使ってファイルを選び、次の内容を依頼します。

   参照ファイルの企業名と案件名を残し、作業概要を一文でまとめてください。

   直近の通信と「最近の通信」で、ファイルに由来する企業名と案件名の置換を確認します。
   会話中に複数の送信が発生する場合は、今回の時刻に対応する結果を探します。

5. 任意の置換語を試す場合は、企業名の行で「編集」を選び、
   「置換後の表記」を「顧客A」にしていずれかの手順を繰り返します。
   回答にも「顧客A」が残ることを確認します。

■ マスキングルールを共有する

対象の行にチェックを入れ、「選択分を書き出す」を押すと JSON ファイルが保存されます。
受け取った人は「JSONを読み込む」でファイルを選び、プレビューで追加件数を確認します。
同じキーワードが登録済みの場合は、読み込む側の設定が優先されます。
共有ファイルにはマスキング対象のキーワードの原文が含まれます。社内の承認済みの経路で共有してください。

■ 動作状況の見方と試用の終了

「キーワードの一致なし」は、対象の本文を検査して登録済みのキーワードに一致する箇所がなかったという結果です。
「内容を確認できなかった」は、解析できずにゲートウェイが送信を止めたという結果です。
「Kiro の対象通信を待機中」は、対象のリクエストが観測されていない状態です。
このままの場合は、試用担当者が Kiro の接続先とログを確認してください。
Kiro のバージョン、チャットかファイル参照か、表示された結果を控えると切り分けできます。
接続確立と両方の置換を確認してから、試用の対象を広げてください。

終了時は Kiro のプロキシ設定を元に戻し、ゲートウェイを終了します。
試用担当者は CA の拇印を照合し、登録した証明書だけを信頼ストアから取り除きます。
ユーザーのストアに登録した場合は certutil.exe -user -delstore Root <拇印> が使えます。
